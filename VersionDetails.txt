## Version 0.3
**Date:** 2026-04-05
**Summary:** Major feature update - Student passwords, privacy enhancements, teacher management, and bilingual support.

### Changes & Improvements:
- **Task 1 - Student Password Requirements**: Replaced access code login with email+password authentication. Students create passwords during signup. Added `password_hash` column to Student model (nullable for backward compatibility).
- **Task 2 - Transfer Subject Between Teachers**: Added admin-only route `/admin/transfer/subject/<id>` to change subject teacher assignment. UI includes dropdown to select new teacher with confirmation.
- **Task 3 - Combined Translation Toggle**: Removed per-page floating translation button from `page.html`. Content now displays based on global locale only (simplified UX).
- **Task 4 - Anonymous Student Names**: Teachers now see "Student #123" instead of real names in analytics. Admins see actual names. Applied to both analytics view and student detail view.
- **Task 5 - CSV Export Restricted**: Grade and student answer CSV exports now restricted to admins only. Teachers cannot download student data.
- **Task 6 - Student Self-Deletion**: Students can delete their own account from dashboard. Personal data is anonymized (name cleared, email/password set to NULL) but exam results retained for analytics. Includes confirmation checkbox.
- **Task 7 - Teacher Name Display**: Added `show_name_on_subject` boolean to User model. Teachers can opt-in to display their name on subject pages. Setting available in teacher edit form.
- **Task 10 - Kurdish About Us**: Added `content_kurdish` column to SiteInfo model. About Us page now supports bilingual content with separate TinyMCE editors for English (LTR) and Kurdish (RTL).

### Database Schema Changes:
- `Student.password_hash` (String(60), nullable)
- `Student.access_code` changed to nullable
- `User.show_name_on_subject` (Boolean, default=False)
- `SiteInfo.content_kurdish` (Text, nullable)

### Files Modified:
- Models: `app/models.py`
- Forms: `app/forms.py`
- Routes: `app/routes/auth.py`, `app/routes/student.py`, `app/routes/teacher.py`, `app/routes/analytics.py`

## Version 0.3.3
**Date:** 2026-04-01
**Summary:** Fixed Kurdish Translation Toggle Cache Issue.

### Changes & Improvements:
- **Bug Fix**: Resolved critical issue where language toggle was not switching translations to Kurdish despite session being updated correctly.
- **Root Cause**: Flask-Babel was caching the locale upon first access, preventing dynamic language switching during the same request cycle.
- **Solution Implementation**: 
  - Added `has_request_context()` checking in `select_locale()` to prevent RuntimeError when accessing session outside request context.
  - Enhanced debugging with detailed logging in `select_locale()` and `set_lang()` routes to trace language switching flow.
  - Added `flask_babel.refresh()` call in `/set-lang/<lang>` route to force cache refresh after session update.
  - Created `/test-lang` debug endpoint for real-time translation verification.
- **Backend Refactoring**: Improved session handling and locale selection logic with proper fallback mechanisms.
- **Testing**: Comprehensive test suite verified language switching works correctly in both directions with proper RTL support.
- Snapshotted as `version_0.3.3`.
